# DD 初始化副作用方案复查（2026-11-24）

本轮为资料调查，不修改输入后端、不替换驱动、不运行初始化或发送输入。

## 核实的来源

- https://github.com/ddxoft/master/issues/73 ：初始化后自动按 Windows 键；回复称尚未解决，使用再次按 Win 补偿；另有“貌似远程修复了？”的猜测，没有厂商确认或复现步骤。
- https://github.com/ddxoft/master/issues/74 ：同类问题及其他用户确认，未见解决方案。
- https://github.com/ddxoft/master/issues/106 ：另一发行包初始化按 Win 的报告，目前无评论。
- https://github.com/ddxoft/master ：本次 contents API 返回 README.md、hid.7xxxx.7z，未看到公开的无副作用初始化接口说明或可据此确定修复的版本记录。本轮没有下载或运行替代二进制。
- https://github.com/rpdg/godd ：封装文档建议进程内单例、DLL 保留至退出；指出行为依赖配套驱动与 DLL。当前项目已经是进程内一次初始化，重复开始/停止不重复初始化。
- https://github.com/oblitum/Interception ：独立驱动方案，README 标注测试范围 XP 至 Windows 10、安装需管理员权限，许可证按用途区分。不能据此保证当前 Windows 或剑三兼容，也不能说无副作用。

本地已有日志将 RWin False→True 定位在 DD_btn(0) 期间；鼠标跳动目前依赖用户报告及新增坐标诊断。缺乏公开 DD 实现，不能从这些证据定位其内部原因。

## 可选方案

1. 厂商提供修复版或明确说明的无副作用初始化接口：从根源消除事件的首选，但本次未找到可验证的现成版本。需配套签名、版本与实测，不能随便混换 DLL。
2. 同一进程托盘常驻：关闭窗口时停止执行、释放按键后隐藏，重新打开复用已初始化实例；真正退出才终止。减少每次开窗口的初始化，不能消除首次初始化或进程重启时的副作用。需要单实例唤醒和明确退出入口；本轮未实施。
3. 管理员权限下独立复测 SendInput：现已确认原热键问题与权限相关，旧输入失败记录不能自动代表严格同权限对照结果。应在独立探针中验证，不覆盖已能用的 DD。标准 API 不要求 DD 初始化，但目标是否接受输出完全待测。
4. Interception 等不同后端：作为独立兼容性评估，安装及设备依赖成本高，不是已验证修复；不为消除初始化闪动立即更换现有工作驱动。

再次按 Win、恢复鼠标、隐藏光标等都属于补偿，不能证明用户无感。全局阻断或限制输入还会影响真实操作及故障恢复，不作为默认补丁。

## 建议

短期优先托盘常驻，保留已成功的 DD 输出和管理员热键监听，明确首次初始化仍存在问题。若要求每次冷启动也完全没有 Win/鼠标事件，则需要验证无此副作用的厂商版本或其他输入后端；目前没有证据支持对现有 DD 包承诺这一点。
