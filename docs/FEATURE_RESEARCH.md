这是常见功能归纳，不是市场占有率排名。项目 JSON 不声称兼容厂商宏文件格式。

状态呈现采用工具型界面的通用规则：保留清楚的状态文字（运行中、监听中、已停止），用低面积的绿色/蓝色/灰色强调状态，不依赖图标像素细节或颜色单独传意。此处是界面设计取舍，并非对某款软件视觉实现的逐像素复刻。

## 实现

手动初始化：构造窗口只创建 DeferredDdKeyboard；点击初始化后工作线程调用 Initialize → DdNativeKeyboard → DD_btn(0)。成功才设置 IsInitialized、开放编辑与注册快捷键。失败保持锁定且写日志，需重启；关闭期间初始化返回不会重新注册热键。

初始化入口不调用 DD_key，不启动重复。界面和命令均检查可用状态。DD 自身的 Win/鼠标副作用尚未根治。

配置复制包含独立的步骤对象。导入使用已有版本迁移机制，完整校验后追加；导出当前配置、覆盖前对话框确认，禁止选择当前主配置路径。非法按键、间隔、快捷键重复或序列/快捷键冲突均被拒绝。

## 方案编辑向导 · 1.3.0

方案编辑迁移到单独窗口并拆成触发、流程、重复三个步骤。当前工作流模式写入配置 v5；v1-v4 配置根据步骤数量迁移为单键或顺序模式。颜色触发配置折叠在触发页，当前窗口在采样时最小化。运行状态使用文字与窄色条，不用窗口标题中的 Unicode 方块/圆点字符。编辑与运行继续使用同一份 ViewModel 和既有调度、颜色采样服务。

本轮回归：Core 45 项通过。Windows 侧其余 42 项通过，1 项真实桌面颜色/鼠标交互测试在等待监听就绪时超时；该测试依赖交互桌面，本次环境未能完成验证。WPF Debug 构建通过，0 警告、0 错误。未初始化 DD，未发送按键。

## 被动热键与方案激活池 · 1.3.2

启停键改为只观察并放行，删除 `RegisterHotKey` 路径。所有方案的开始、停止和备用开始键都绑定到被动接收器；同时触发的方案快照进入有界 FIFO 激活池，单一 runtime 串行执行以保护共享输出设备。全局停止取消当前项、清空队列、停止颜色监听并释放输出按键。颜色监听按方案独立运行，边沿触发后提交到相同激活池。准备前窗口压缩到 500×320，准备后展开至工作尺寸。

激活池 FIFO 与取消测试通过。最终全套运行：Core 45 项通过；Windows 45 项通过、1 项失败。失败项 `ScreenColorTests.ReadsActualVisibleWindowPixels` 在等待模拟鼠标点击时超时；过滤桌面交互后的 Windows 测试 42 项全部通过。未初始化 DD，未进行应用内实测。

## 激活池选择与限时精度 · 1.3.3

方案选择列表直接呈现“激活池”勾选状态。只有池内方案注册被动启停热键，手动开始和颜色监听入口也都检查池成员；移出池后不会因快捷键或颜色条件被触发。新增方案仍默认加入池，复制方案默认不加入。迁移旧版配置时仅首个方案默认加入池，用户可自行调整。

限时重复将持续时间拆成秒与 0–999 毫秒两项，运行截止时间和颜色触发校验使用两项合成的总时长。回归测试覆盖旧配置的小数秒迁移、池成员默认值和 1.3 秒实际截止行为。

## 重复触发与顺序间隔 · 1.3.4

同一方案的重复触发在激活池中合并为一个请求。默认策略将当前有限时长的截止点移到最后一次触发之后；可选忽略重复触发而保持原截止点。此策略只改变软件内部的任务调度，监听器仍放行物理输入。不同方案仍在共享队列中串行执行。

流程表格将间隔标为“到下一键间隔”，定义为当前键释放后等待到下一步骤按下；末步骤的间隔用于进入新一轮的首步骤。配置 v7 将历史 start-to-start 间隔迁移为释放后的间隔，并保留旧配置的按下时长、既有激活池选择和毫秒持续时间。

## 分组与独立触发总览 · 1.3.5

本轮实际读取 [Keyboard Maestro Macro Groups](https://wiki.keyboardmaestro.com/manual/Macro_Groups)，快照位于 `.artifacts/features/keyboard-maestro-groups.html`。其分组把宏按用途组织，并支持控制何时可触发。本项目采用按用途分组和批量参与/停用，不新增按应用切换。尝试读取 Microsoft 的桌面流程管理页面返回 404，未作为设计证据。

选择与启用分开：蓝色边框仅表示编辑对象，绿色文字“已参与触发”表示会响应触发键，顶部独立汇总参与方案及分组、主触发键。管理入口与我的配置同行，名称和分组在编辑窗口设置；新分组直接输入名称，空值归为“未分组”。组是组织方式，批量停用不会删除方案。

删除运行状态中的高度重设，开始/停止只更新状态。WPF 实际布局测试发现实时换组会移除/插入条目，导致列表选择丢失，已在控件层保留换组前选择；不会恢复已删除条目。配置升为 v8，避免 v7 导入时重复扣除按下时长。
