# key_flow

Windows DD 重复按键工具，.NET 8 / WPF。

## 使用

安装用户：运行 `dist/key_flow_setup_1.3.2_x64.exe`，安装后从桌面或开始菜单打开 key_flow。无需另装 .NET。可在 Windows 设置 → 应用 → key_flow 中卸载。

源码用户：双击 `start_key_flow.cmd` 构建并启动，或运行 `tools/build_installer.ps1` 生成安装包。程序启动请求管理员权限。

1. 初次打开只显示紧凑的准备窗口。点击“准备使用”后，主界面展开；此前配置编辑、保存、置顶、开始、停止和热键不可用。
2. 初始化成功后，在主窗口选择方案并点击“编辑所选方案”。编辑窗口按“触发 → 流程 → 重复”分步设置；页签可直接切换，也可用前后按钮导航。
3. 在“流程”页选择单键重复或多键顺序执行；整个流程按“重复”页设置持续运行或到时停止。保存方案后回到主窗口开始。

初始化可能触发 Win 菜单或鼠标移动；手动按钮让用户决定初始化时机，不代表消除了厂商副作用。初始化不自动执行序列。失败需重启，不反复加载。

## 配置

支持新建、重命名、复制、删除（至少保留一个）、JSON 导入和导出当前配置。导入追加，不替换现有配置；点击“保存配置”才写入本地。保存使用原子替换并保留 `.bak`。

配置与日志位于 `%LOCALAPPDATA%\key_flow\config.json` 和 `key_flow.log`。首次源码运行可复制旧配置且不覆盖已有配置，原文件不删除；本机已有配置已迁移并核对哈希。更新与卸载保留个人数据及系统共享输入组件。

完整构建与验证记录见 [安装交付](docs/key_flow_installation.md)。

## 架构

- Core：重复调度、配置存储、运行时。
- Windows：DD 输出、键盘监听、诊断、配置复制与校验。
- App：模块化 WPF；MainViewModel.Setup.cs 负责手动初始化与配置交换。
- tests：核心和 Windows 测试。运行 `dotnet test key_flow.sln`。

输出仅用 DD；启停热键只通过 MouseKeyHook、Raw Input 和状态轮询观察，不拦截或占用按键。方案触发会排入共享激活池，并按 FIFO 顺序执行；停止键和紧急停止会取消当前执行、清空等待项并释放按键。独立 Demo 和旧启动入口已删除，历史可由 Git 恢复。

参见 [功能调研](docs/FEATURE_RESEARCH.md)、[初始化问题](docs/DD_INITIALIZATION_OPTIONS.md)、[热键研究](docs/HOTKEY_LIBRARY_RESEARCH.md)。研究文件保留历史记录，当前使用方法以本文为准。

## 快速切换与单键开关

准备完成后，配置以卡片列表显示，点击即可切换；当前卡片高亮，数量较多时可滚动。切换会清空步骤选择、取消未完成录入并重新绑定所有方案的快捷键。运行期间不可切换，先停止再选择配置。

开始/停止按钮固定在上方。配置区的“单键开关”勾选后，开始键同时承担停止功能，不再注册原停止键；取消勾选恢复独立启停键。紧急停止 Ctrl+Shift+F10 始终保留。选项按配置保存，复制、导入、导出保留该值；旧配置默认不启用。修改后点击保存配置。

本轮验证：45 项测试通过，涵盖单键模式序列冲突校验、JSON 保存及旧配置兼容、长按重复抑制、两路接收去重和松开再按。通过假数据渲染实际 WPF 控件检查布局，未调用 DD、未在游戏中实测。

## 组合键

按键序列与启停键支持 Ctrl、Alt、Shift 加一个主键，例如 Shift+1、Ctrl+Shift+1。点击按键按钮后，先按住修饰键，再按主键；整组松开后恢复快捷键监听。单独的修饰键在松开时录入。支持原有 D1 格式，新增录入显示 1，配置仍保存字符串。

DD 输出按 Ctrl/Alt/Shift、主键顺序按下，逆序释放；失败按下保留状态供清理，部分释放失败仍继续尝试其他键。校验拒绝可能触发启停键或紧急停止键的序列。暂不支持 Win 组合键或 A+B 这类多个普通主键。

验证：56 项测试通过，新增解析、旧单键兼容、修饰键录入与释放、DD 调用顺序、部分失败清理及快捷键冲突测试。测试使用假 DD 接口，未发送真实组合键，游戏内效果待实测。

## 限时重复与屏幕取色（1.1.0）

例如按 X 或 F 后重复 E 六秒：开始键录入 X、备用开始键录入 F，关闭单键开关，持续时间填 6，序列只保留 E，重复间隔填 80 ms。保存配置后任一开始键触发同一任务，到时自动停止；运行中再次触发不排队、不重置计时。填 0 保留持续运行。停止键和紧急停止仍可提前结束。

展开“屏幕取色与激活判断”，点击“取色（3 秒后）”，把鼠标移到已经激活的目标位置。程序保存该点的物理像素坐标和颜色；“检测一次”比较当前颜色与目标颜色。容差表示各 RGB 通道允许的最大差值（0–255）。每个配置保存一个检测点，不同位置可用不同配置。

可选勾选“仅在颜色匹配时输出按键”：每次按下前检查，未匹配时每 50 ms 重试，匹配后继续原序列，持续时间仍计时；读取失败则停止并清理按键。未勾选时，颜色检测不影响按键输出。读取的是可见桌面，遮挡、窗口移动、缩放或显示模式改变后需要重新取色；单像素匹配并不等于识别应用内部业务状态。

配置升级为 v3；v1/v2 加载后保留原序列，默认不限时、无备用键、关闭颜色条件。不自动写回用户配置，保存才升级。旧版程序不能读取 v3，请保留备份。

设计与测试边界见 [限时重复与取色](docs/TIMED_REPEAT_AND_COLOR.md)。

## 颜色自动触发（1.2.0）

在取色设置中勾选“色块激活后自动运行当前按键流程”，开始按钮/热键会开启监听。稳定未激活后，再稳定激活才执行一次已有按键序列，到期后继续监听。开始时已经激活不立即执行，连续亮起不重复执行。确认时间默认 100ms，可设置；触发模式持续时间必须大于零。

“全部停止”和停止快捷键同时取消监听与按键，紧急停止保留。监听期间配置锁定，防止运行中改变条件。配置 v4 兼容迁移旧文件，默认关闭新功能。

详细操作、架构与 84 项测试结果见 [颜色触发流程](docs/COLOR_TRIGGER_WORKFLOW.md)。

支持划定取色区域，并在用户点击瞬间分别采集激活色和未激活色。采集窗口暂时收起，点击只作为取色时刻，不会传给目标程序；Esc 取消。两色模式把其他颜色视为未知，避免把动画过渡颜色当成恢复状态。区域采用九点均值，建议选择均匀的小色块。

## 仓库命名与本地开发

项目统一使用 `key_flow`，仓库目录为 `key_flow`。主解决方案 `key_flow.sln`；项目目录为 `src/key_flow_app`、`src/key_flow_core`、`src/key_flow_windows` 及对应 `tests/key_flow_*_tests`。命名空间与项目同名；C# 类型、方法和 WPF 控件名称继续遵循语言原有惯例。

1. 安装 .NET 8 SDK，执行 `dotnet test key_flow.sln`。
2. 按 `dependencies/dd/README.md` 准备本地输入组件，双击 `start_key_flow.cmd`。
3. 安装 NSIS 后运行 `tools/build_installer.ps1 -NsisPath <makensis.exe> -DriverSource <厂商组件目录>`。图标已入库，重建图标需 Python 和 Pillow。

版本 1.3.2 使用 `%LOCALAPPDATA%/key_flow`、`key_flow.exe`、`key_flow.log`、`key_flow_setup_1.3.2_x64.exe`。首次运行只在新配置不存在时复制旧产品配置，不删除或覆盖旧数据。历史路径字面量仅用于迁移兼容。旧产品的已安装副本不会因源码改名被自动删除，可在确认迁移完成后从系统设置卸载旧副本。

Git 仅提交源码、文档和图标；构建输出、安装包、本地输入组件 DLL 与 `.artifacts` 均忽略。上传 GitHub 时推送仓库即可，不需要上传整个本地文件夹；本次没有创建远程仓库或推送。

## 1.2.2 界面入口

取色与激活流程面板默认展开并移到配置编辑区顶部。机器上如果同时保留旧版 KeyFlow，请从 `C:\Program Files\key_flow\key_flow.exe` 打开新版，或重新安装 `dist/key_flow_setup_1.2.2_x64.exe` 后使用新版快捷方式；旧版 `C:\Program Files\KeyFlow` 不包含颜色流程功能。

## 1.3.0 方案编辑

方案编辑移入独立窗口，并分成触发、流程、重复三页。颜色设置仅在启用屏幕颜色触发时展开；取色/框选时最小化当前编辑窗口。流程类型明确分为单键重复和多键顺序执行，切换为单键时会确认后保留第一步。重复规则分为持续重复和限时重复。顶部运行状态使用文字与语义色条表达，不再在窗口标题中放置像素式状态字符。

## 1.3.2 被动热键与方案激活池

移除 `RegisterHotKey` 注册，改为被动监听并继续传递物理按键。所有方案的开始、停止和备用开始键都会监听；同一快捷键触发多个方案时，多个方案快照会进入 FIFO 激活池，使用单一输出运行时依次执行，避免并行争用输出设备。停止键和紧急停止会取消当前执行、清空等待项并释放按键。多个颜色监听也可同时运行，触发后共享同一激活池。

未准备前窗口缩为 500×320，准备成功后展开到 700×800。激活池新增 FIFO 执行与取消测试；本轮 Core 45 项通过，Windows 44 项通过。另有 2 项依赖可见桌面 WPF PresentationSource 的颜色像素测试在当前会话未通过。

## 1.3.1 编辑窗口崩溃修复

修正只读流程状态绑定到 WPF 单选按钮时的默认双向绑定错误。该错误会在打开编辑窗口布局期间抛出未处理异常；当前流程与重复规则状态均明确使用单向绑定，并由命令更新配置。
